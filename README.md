# SmartBrew AI — Java Prototype

## 1. System Overview

SmartBrew AI is a console-based Java prototype of an intelligent coffee vending system. It demonstrates core software engineering functionality for customers and administrators without requiring physical NFC hardware, a real payment gateway, or a database.

### Functionalities

1. **Customer authentication:** Sign in using a simulated NFC token.
2. **Preference management:** Select milk type, coffee strength, and serving temperature.
3. **Menu browsing:** View available beverages and prices in Swedish kronor (SEK).
4. **Inventory checking:** View ingredient stock and check whether a beverage can be prepared.
5. **Saved recipes:** Create and save a customized beverage recipe.
6. **Recommendations:** Receive a rule-based beverage recommendation based on preferences.
7. **Order processing:** Select a beverage, confirm simulated payment, deduct ingredients, and print a receipt.
8. **Mood assistant:** Enter a mood and receive a simple beverage suggestion.
9. **Administrator/refill:** Sign in as an administrator and add ingredient stock.
10. **Diagnostics and export:** Review low stock, inspect basic system status, and export successful transactions to CSV.

### Demo credentials

- **Customer NFC token:** `NFC-1001`
- **Administrator PIN:** `1234`

These credentials are for demonstration only and are hardcoded in the source code.

### Important limitations

- NFC authentication and payment are simulated; no physical NFC reader or real payment service is used.
- Inventory, preferences, saved recipes, and transactions are stored in memory and are reset when the program restarts.
- Transaction export writes a CSV file to the program's current working directory.
- Recommendations use simple predefined rules; they are not generated by a machine-learning model.
- The application is a learning prototype, not a production-ready vending system.

## 2. Environment & Prerequisites

### Required software

| Component | Requirement |
|---|---|
| Java Development Kit (JDK) | JDK 17 or newer recommended |
| Java compiler | `javac`, included with the JDK |
| Java runtime | `java`, included with the JDK |
| IDE (optional) | IntelliJ IDEA, Eclipse, or Visual Studio Code with Java support |
| Operating system | Windows, macOS, or Linux |
| External libraries | None |
| Database | Not required |
| Internet connection | Not required to compile or run |

The source uses standard Java libraries only, including collections, date/time utilities, and file writing. Java 17 or newer is recommended because the program uses modern `switch` expressions.

### Verify the Java installation

Open a terminal (Command Prompt or PowerShell on Windows) and run:

```bash
java -version
javac -version
```

Both commands should report Java 17 or a newer compatible version. If either command is not recognized, install a JDK and configure your system's `PATH` and `JAVA_HOME` as appropriate.

## 3. Execution Guide

### Run from an IDE

1. Open IntelliJ IDEA, Eclipse, or Visual Studio Code with Java support.
2.  Open a Java project configured for JDK 17 or newer.
3. Open the `SmartBrew.java` to the source directory.
4. Run the Class from the top green button.
5. Use the IDE's console to enter menu choices and view results.

## 4. How to Test All 10 Functionalities

Use the following manual test walkthrough. Record the actual outcome for your lab report; do not mark a test as passed until you have run it.

### 1. Customer authentication

1. Start the program and choose `1` at the main menu.
2. Enter `NFC-1001`.
3. Verify that authentication succeeds and the customer menu appears.
4. Sign out and try again with `NFC-9999`.
5. Verify that the invalid token is rejected.

**Expected result:** Only the configured demo token is accepted.

### 2. Preference management

1. Sign in as the customer.
2. Choose `1` in the customer menu.
3. Select milk: `1` for Regular, `2` for Oat, or `3` for None.
4. Select strength: `1` for Mild, `2` for Medium, or `3` for Strong.
5. Select temperature: `1` for Hot or `2` for Cold.
6. Verify that the updated preferences are displayed.

**Expected result:** Valid choices are stored and displayed. Invalid choices are rejected.

### 3. Menu browsing

1. From the customer menu, choose `2`.
2. Verify that Espresso, Americano, Cappuccino, Latte, and Mocha are displayed.
3. Check the displayed prices.

**Expected result:** The five beverages and their prices are shown in SEK.

### 4. Inventory checking

1. Choose `3` in the customer menu.
2. Verify that the current ingredient quantities are displayed.
3. Select a beverage to check ingredient availability.
4. To test insufficient stock, temporarily set a required ingredient quantity to `0` in `initialize()` in the source code, recompile, and rerun the application.

**Expected result:** A drink is available when all required ingredients are in stock and unavailable when any required ingredient is insufficient.

### 5. Saved recipes

1. Choose `1` to configure customer preferences.
2. Choose `4` to create and save a recipe.
3. Select a base beverage.
4. Choose `8` to view saved recipes.
5. Optionally, save a second recipe and verify that both appear.

**Expected result:** The customized recipe appears in the saved recipe list.

### 6. Recommendations

1. Set the customer's preferences using option `1`.
2. Choose `5` in the customer menu.
3. Test different combinations, such as Strong strength, Oat milk, Regular milk, and no milk.

**Expected result:** The prototype recommends a beverage according to its predefined preference rules. Note that this recommendation method does not currently combine mood with preferences.

### 7. Order processing, simulated payment, and receipt

1. Choose `6` in the customer menu.
2. Select a beverage.
3. Enter `1` to confirm simulated payment.
4. Verify the receipt and ingredient deductions.
5. Repeat the process but enter `2` to cancel payment.
6. To test insufficient stock, set one required ingredient to an insufficient quantity and try ordering that drink.

**Expected result:** A confirmed order produces a receipt, records a transaction, and deducts ingredients. A cancelled payment does not deduct ingredients or create a successful transaction.

### 8. Mood assistant

1. Choose `7` in the customer menu.
2. Enter `tired`, `stressed`, `sad`, `happy`, or `focused`.
3. Repeat with an unsupported mood such as `bored`.

**Expected result:** Recognized moods receive the corresponding suggestion; unrecognized moods receive the default suggestion.

### 9. Administrator authentication and refill

1. Sign out of the customer menu if needed.
2. At the main menu, choose `2`.
3. Enter administrator PIN `1234`.
4. Choose `1` to inspect inventory.
5. Choose `2` to refill an ingredient, such as Coffee beans, with quantity `20`.
6. Verify the new stock quantity.
7. Try an invalid PIN and verify that access is denied.
8. Choose `0` in the administrator menu to sign out.

**Expected result:** The correct PIN grants access, valid refills increase stock, invalid refill inputs are rejected, and an incorrect PIN is denied.

### 10. Diagnostics and transaction export

1. Sign in as administrator.
2. Choose `3` to view the low-stock report.
3. Choose `4` to inspect system diagnostics.
4. Place one or more successful customer orders if you want transaction rows in the export.
5. Return to the administrator menu and choose `5`.
6. Find `smartbrew_transactions.csv` in the application's current working directory.
7. Open the CSV in a text editor or spreadsheet application and inspect its header and rows.

**Expected result:** Diagnostics display application information, low-stock items are flagged at or below the threshold of five units, and successful transactions are exported to CSV.

To test the low-stock warning, temporarily initialize an ingredient to `5` or fewer units, then recompile and restart the program.

## 6. Known Limitations and Future Improvements

- Replace hardcoded demo credentials with secure authentication.
- Integrate a real NFC reader if hardware authentication is required.
- Use a database to persist customers, preferences, recipes, stock, and orders.
- Integrate a payment sandbox rather than treating confirmation as a successful simulated payment.
- Improve recipe calculations so milk and strength changes correctly adjust all ingredient quantities.
- Combine mood and beverage preferences in the recommendation logic.
- Add automated unit tests and integration tests.
- Consider a JavaFX or Swing interface for a touchscreen-style experience.
- Add input validation, audit logging, and appropriate protection for exported transaction data.

---

After compilation and execution, generated `.class` files and `smartbrew_transactions.csv` may also appear in the working directory.

## 7. Summary

SmartBrew AI is a self-contained Java console prototype for demonstrating ten core coffee vending system functionalities. It requires JDK 17 or newer, has no third-party library or database dependencies, and can be built and run using IDE.
